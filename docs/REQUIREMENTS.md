# Requirements

Requirements have stable IDs. Do not reuse an ID for different behavior; mark superseded requirements and link the replacement. `Priority` is `MUST`, `SHOULD`, or `COULD`. Status describes the requirement decision, not implementation progress.

| ID | Priority | Requirement | Acceptance signal | Status |
| --- | --- | --- | --- | --- |
| REQ-001 | MUST | AutoDev is an installable Python 3.11+ package with an `autodev` console entry point and packaged schemas and templates. Its pre-release version is `2.0.0a1`, and its sole runtime dependency is `jsonschema>=4.26,<5`. | A built wheel has the required metadata, entry point, and resources; `autodev version` prints `2.0.0a1`. | ACCEPTED |
| REQ-002 | MUST | The public architecture assigns contracts and state transitions to `ControlPlane`, run lifecycle to `RunController`, and one execution attempt to a Codex or Fake `ExecutionEngine` adapter. | Architecture and ADR-0001 define the three seams without shallow per-component interfaces. | ACCEPTED |
| REQ-003 | MUST | `.autodev/` is the only V2 canonical state; `.agent/` is accepted only as V1 migration input or a frozen backup. | Validation and migration tests prove that V2 never reads `.agent/` as live state after migration. | ACCEPTED |
| REQ-004 | MUST | Durable V2 safety, quality-routing, migration, runner, and completion behavior is recorded in stable requirements and architecture decisions. | Each milestone Task references stable IDs and the ADR index covers the binding architectural choices. | ACCEPTED |
| REQ-005 | MUST | The existing V1 public workflow remains passing while V2 is developed as an installable package. | All 14 pre-existing V1 unit tests pass during the foundation slice. | ACCEPTED |
| REQ-006 | MUST | V2 schemas use JSON Schema Draft 2020-12 with the `jsonschema` standard format checker; the V1 simplified validator is not carried into V2. | Schema tests exercise valid, invalid, and format-invalid documents through `jsonschema`. | ACCEPTED |
| REQ-007 | MUST | Canonical writes are validated, revision-checked, atomic, and evented; only `ControlPlane` may mutate canonical state. | Fault-injection and revision-conflict tests never observe a partially committed state. | ACCEPTED |
| REQ-008 | MUST | Project, Task, and Attempt states and legal transitions match the published state machines; illegal transitions are rejected without mutation. | Transition-table tests cover every allowed edge and representative forbidden edges. | ACCEPTED |
| REQ-009 | MUST | A Task has one structured `contract.json`; it is editable in DRAFT, frozen by hash at READY, and projected to read-only `contract.md`. Reopening with a reason invalidates old claim and evidence. | Contract-hash, projection, mutation, and reopen tests pass. | ACCEPTED |
| REQ-010 | MUST | Task contracts include objective, requirement IDs, dependencies, priority, blocking flag, risk, quality mode, change classes, allowed paths, out-of-scope items, identified acceptance criteria, structured validation commands, and prohibited actions. | Schema validation rejects a contract missing any required field or containing an unsafe validation command. | ACCEPTED |
| REQ-011 | MUST | Validation commands are represented as `argv[]`, project-relative `cwd`, and timeout, run with `shell=False`, and are restricted by executable and working-directory policy. Tasks cannot define environment variables. | Security tests reject shell strings, disallowed executables, out-of-root directories, and task environment fields. | ACCEPTED |
| REQ-012 | MUST | Requirements parsing extracts only ID, priority, status, and acceptance signal from `docs/REQUIREMENTS.md` and does not duplicate requirement prose into canonical state. | Parser tests preserve stable identifiers and reject malformed or duplicate rows. | ACCEPTED |
| REQ-013 | MUST | `autodev init` installs project contracts, canonical state templates, and the `autodev-builder` agent template without copying CLI source or framework tests. It uses Codex's built-in explorer. | Fresh and merge initialization tests inspect the exact installed file set and overwrite behavior. | ACCEPTED |
| REQ-014 | MUST | V1 migration has read-only check, atomic apply, and guarded rollback modes. It uses a packaged checksum manifest and stops on user-modified framework-file conflicts. | Migration fixtures cover bootstrap, active, blocked, false-complete, task/debt conversion, conflicts, repeat apply, and rollback limits. | ACCEPTED |
| REQ-015 | MUST | The runner uses an atomic directory lock with heartbeat, refuses live locks, and may recover a same-host stale lock after proving its PID is dead. | Competing-process and stale-lock tests permit exactly one owner and preserve lock evidence. | ACCEPTED |
| REQ-016 | MUST | A target has Git HEAD and a clean tracked/untracked source baseline outside `.autodev/**` before claim. A run then uses one isolated Git worktree, verifies protected and allowed paths, collects a binary-safe patch, and reapplies it only when the source fingerprint still matches. | Tests cover missing HEAD, dirty source, AutoDev-only changes, cleanup, binary changes, path violations, crash retention, and concurrent source modification. | ACCEPTED |
| REQ-017 | MUST | `ExecutionEngine` explicitly exposes live-authorization metadata, no-model `preflight(...)`, and `execute(AttemptRequest)`; it has exactly two initial adapters: real `CodexExecEngine` and deterministic `FakeCodexRunner`. | Contract tests drive identical runner outcomes through fake results and validate the Codex command/protocol boundary. | ACCEPTED |
| REQ-018 | MUST | Codex runs fresh for ordinary attempts with correctly scoped global/exec arguments, approval `never`, BUILD permission profile `:workspace`, Reviewer profile `:read-only`, MCP and hooks cleared, JSONL output, and a Codex-strict output schema. AutoDev does not expose sandbox backend selection. | Doctor, strict-schema, false-positive probe, and command-construction tests prove every control is applied or report not-ready. | ACCEPTED |
| REQ-019 | MUST | Each run processes one deterministically selected READY Task unless explicit `--until complete-or-blocked` mode is requested. Selection orders priority, satisfied dependencies, creation time, then ID. | Scheduler tests produce a stable selection and stop after one accepted or terminal Task by default. | ACCEPTED |
| REQ-020 | MUST | Attempts enforce idle and hard timeouts, an infrastructure retry limit, process-group cancellation, and a STOP escalation from interrupt through terminate to force-kill while preserving recovery artifacts. | Fake/subprocess tests cover every timeout, retry, and stop stage. | ACCEPTED |
| REQ-021 | MUST | Quality routing requires an independent fresh read-only Reviewer for HIGH, HARDENING, architecture, public-interface, security, migration, shared-schema, milestone-integration, or threshold-rework work. | Policy matrix tests cover every mandatory-review trigger and the BUILD LOW/MEDIUM exemption. | ACCEPTED |
| REQ-022 | MUST | `PASS_WITH_DEBT` is allowed only for non-blocking LOW/MEDIUM issues, and every accepted item records a stable ID, source Task, reason, severity, module, and fix-before milestone. | Debt-gate tests reject safety, data-loss, failed-acceptance, public-interface, and unrecorded debt. | ACCEPTED |
| REQ-023 | MUST | Runner-produced evidence independently records hashes and references for contracts, proposals, diffs, validations, reviews, checkpoints, and accepted requirement signals. Agent proposals cannot directly write top-level state. | Evidence-index tests verify provenance and reject missing or mismatched artifacts. | ACCEPTED |
| REQ-024 | MUST | Semantic stagnation compares Task/phase, acceptance evidence, failed-check signatures, allowed-path diff hash, and blocking review findings. Logs, summaries, or weaker tests alone are not progress. | Repeated Fake attempts cross the configured no-progress threshold and produce the required escalation. | ACCEPTED |
| REQ-025 | MUST | Budgets default to 30 run iterations/four hours; four work attempts, two reworks, and two consecutive stagnations per Task; 600-second idle and 2400-second hard timeouts per Attempt; and one infrastructure retry. | Config and boundary tests enforce each default and reject exhausted execution. | ACCEPTED |
| REQ-026 | MUST | Recoverable infrastructure failures pause the project, user stops produce STOPPED, product/authority/contract/budget impasses produce BLOCKED, and only unrecoverable state corruption produces FAILED. | Outcome-routing and resume tests preserve the distinct states and smallest unblock action. | ACCEPTED |
| REQ-027 | MUST | Project COMPLETE is derived only when all blocking Tasks and MUST requirements have accepted evidence, no blocking debt/run/lock/blocker remains, and project-level full validation passes. An agent completion proposal has no authority. | Completion tests deny every missing prerequisite and accept only the full invariant set. | ACCEPTED |
| REQ-028 | MUST | CLI exit codes are stable: 0 success/accepted, 1 invalid argument or contract, 2 not ready/paused, 3 blocked, 4 stopped, and 5 unrecoverable infrastructure failure. | Command-level tests assert each documented outcome. | ACCEPTED |
| REQ-029 | SHOULD | Linux, macOS, and WSL are supported initially; native Windows process and lock semantics may be added later. | Supported-platform CI passes and native-Windows limitations are explicit. | ACCEPTED |
| REQ-030 | MUST | CI and ordinary tests use `FakeCodexRunner`; live Codex execution is a separate smoke requiring explicit user authorization and exact `AUTODEV_LIVE_CODEX=1`. CLI, Runner, and Engine reject before STOP cleanup, Task claim, state transition, artifact creation, or model launch when the gate is absent. A real attempt is not release evidence unless the disposable smoke reaches ACCEPTED and COMPLETE with required tests and routing evidence. | Tests prove all three live fail-closed boundaries; release checks cannot select `2.0.0` or launch live Codex implicitly, and a BLOCKED/failed smoke cannot be recorded as PASS. | ACCEPTED |
| REQ-031 | MUST | Every Linux live run performs a no-model Codex sandbox preflight before lock, claim, or model invocation. Failure is classified as legacy Landlock incompatibility, bubblewrap bootstrap failure, nested sandbox/container restriction, Codex configuration error, or generic environment/runtime failure; genuine Agent/Task failures remain distinct. `features.use_legacy_landlock` is unsupported/deprecated and never generated, persisted, or recommended. There is no automatic danger-full-access fallback. | Engine, Runner, and doctor tests prove preflight ordering and each diagnostic class. | ACCEPTED |
| REQ-032 | SHOULD | A future explicit `external-sandbox` mode may trust a Docker/devcontainer outer boundary. It requires project configuration plus exact `AUTODEV_EXTERNAL_SANDBOX=1` and must never be selected as fallback. | Tests show the mode fails closed without both opt-ins and normal Codex sandbox failure never selects it. | ACCEPTED |

Allowed statuses: `PROPOSED`, `ACCEPTED`, `SUPERSEDED`, `REJECTED`.
